# Git Workflow and Commit Strategy

## Incremental Commits

Implement features using gradual commits after completing each logical unit of work. Follow the established commit message format:

**Commit Message Format**: `type(file/component): description`

**Examples**:

- `feat(feedPosts.ts): add getUserFeedPosts server action for profile interactions`
- `feat(ProfileFeedContainer.tsx): create reusable container for user activity feed`
- `enhance(PostFactory.tsx): add optional interaction type indicators for profile context`
- `feat(profile/[userId]/page.tsx): implement profile page with activity feed above friends`
- `style(ProfileFeedContainer.css): apply global CSS vars for consistent theming`

## Commit Types

### Primary Types

- `feat`: New feature implementation
- `fix`: Bug fixes
- `enhance`: Improvements to existing functionality
- `refactor`: Code restructuring without functional changes
- `style`: CSS/styling changes
- `update`: Data or content updates
- `config`: Configuration file changes
- `docs`: Documentation updates
- `test`: Adding or updating tests

### Branch Naming Convention

- Feature branches: `feat/descriptive-feature-name`
- Bug fixes: `fix/descriptive-bug-name`
- Updates: `update/descriptive-change-name`
- Refactoring: `refactor/descriptive-refactor-name`

## Commit Guidelines

### DO:

- Make small, logical commits that represent complete units of work
- Use clear, descriptive commit messages
- Include the affected file/component in parentheses
- Use present tense ("add" not "added")
- Keep the description concise but informative

### DON'T:

- **Never use emojis in commit messages**
- Don't make massive commits with multiple unrelated changes
- Don't use vague messages like "fix stuff" or "update code"
- Don't commit broken or incomplete code
- **Never mention in a commit that it was generated by claude or any other agent/llm**

## Example Workflow

```bash
# Create and switch to feature branch
git checkout -b feat/user-profile-updates

# Make changes, then commit incrementally
git add src/components/ProfileCard.tsx
git commit -m "feat(ProfileCard.tsx): add avatar upload functionality"

git add src/utils/imageUtils.ts
git commit -m "feat(imageUtils.ts): create image compression utility for avatar uploads"

git add src/components/ProfileCard.css
git commit -m "style(ProfileCard.css): add responsive styling for avatar component"

# Continue with more commits as you complete logical units...
```

## Integration with TypeScript/Python Projects

### TypeScript/Next.js Projects

- Use component names in commit messages: `feat(UserDashboard.tsx): ...`
- Include utility files: `enhance(authUtils.ts): ...`
- Reference API routes: `feat(api/users/route.ts): ...`

### Python Projects

- Use module names: `feat(user_service.py): ...`
- Include test files: `test(test_user_service.py): ...`
- Reference config files: `config(settings.py): ...`

## File Organization in Commits

When working with your preferred tech stack (TypeScript, Python, Next.js), organize commits by:

1. Backend/API changes first
2. Frontend component updates
3. Styling and UI polish
4. Tests and documentation
5. Configuration updates

This strategy aligns with your serverless AWS deployment goals and containerized backend preferences.
